# V7/V6 保护层加固方案（r10 路线图）

**依据**：外部逆向报告（四层全破、零执行还原 30 个载荷）＋ 两轮源码审计（静态密钥链、运行时 dump 面）
**日期**：2026-09-08
**范围**：`v7/elfrun.c`、`v7/crypto_core.h`、`v7/blobgen.c`、`v7/v7_build.sh`、`v6/shell_script_obfuscator_v6.sh`

---

## 1. 现状判断

native 化这一步的收益已被攻击者报告确认：攻击从"剥一层 bash"升级为"capstone 反汇编 + 密码学复现"，成本上了一个数量级。但四层全部被静态还原的事实同时说明，三个结构性问题没有解决：**密钥随产物发布、绑定熵可枚举、运行时存在零门槛注入口**。另外 r9 已完成的修复（跨上下文指纹 s4 剔除、缺工具 rc=121、冒烟智能化、`_self_dir` 定位 bug）属于正确性范畴，不在本方案重复，本方案只谈对抗强度。

先摆一个关键事实：V6 层已经做对了 per-build 随机化（变量名、结构每构建重排，报告者也只能靠爆破环境熵而不是读固定偏移），而 C 层（elfrun 模板）是**全产物完全相同的固定布局**——报告正是靠这一点（`0x20560c` 固定偏移、`V7ENC`/`V7MAC` 明文标签、SHA 标准常数表）实现了一次逆向、处处适用。P1 的本质就是把 V6 已有的随机化哲学搬进 C 层。

## 2. 威胁模型

| 攻击者 | 能力 | 已证明战果 |
|--------|------|-----------|
| T1 静态逆向者 | 只拿到文件，零执行 | 四层全破，30 载荷解码，还原版运行一致 |
| T2 运行时 dumper | 真机，root + Frida/hook | 未演示，但存在无需 root 的注入口（见路径 C） |
| T3 工具作者 | 一次逆向，产出自动化脚本 | 报告方法可直接量产（固定偏移 + 标准常数定位） |

**资产**：内层脚本的业务逻辑。
**非目标**（诚实边界见 §8）：持口令的合法用户、控制执行环境的 root 攻击者。

## 3. 四条已实锤的攻击路径

| # | 路径 | 根因 | 证据 |
|---|------|------|------|
| A | 静态提密钥 | `V7_SEED[32]` 明文躺在 .rodata 固定偏移 | 报告：密钥在 blob 头 32 字节（0x20560c） |
| B | 环境熵爆破 | L3 密钥原料 = 安卓版本 × ABI × 指纹 ≈ 数百组合 | 报告：两分钟爆破命中（16 / arm64-v8a / 1111） |
| C | BASH_ENV + DEBUG trap | `elfrun.c` 原样透传 `environ`；非交互 bash 启动先 source `$BASH_ENV` | 本轮审计发现，无需 root 即可 dump 明文命令流 |
| D | 通用脱壳机 | C 层算法与布局恒定，明文标签 + 常数表 = 固定路标 | 报告方法的直接推论：对后续所有产物生效 |

报告还暴露一个次要事实：它描述的 L2 防御（PR_SET_DUMPABLE、PATH 净化、`/proc/self/maps` 扫描）与实际源码有出入，其中几项并未实现。清单见 §6.2。

## 4. P0：立即修（决定性收益，极低成本）

### 4.1 关闭 BASH_ENV 注入口（杀路径 C）

**现状**：`elfrun.c` 只拦 `LD_PRELOAD`，其余环境变量原样传给内嵌 bash。非交互 bash 会先展开并 source `$BASH_ENV` 指向的文件，攻击者一行搞定：

```sh
cat > /sdcard/h.sh <<'EOF'
trap 'printf "%s\n" "$BASH_COMMAND" >> /sdcard/dump.txt' DEBUG
EOF
BASH_ENV=/sdcard/h.sh ./protected_elf
```

DEBUG trap 在每条命令执行前触发，`$BASH_COMMAND` 就是明文，包括 `builtin eval` 解出的每个载荷。这招不开 xtrace、不动 PS4、无 LD_PRELOAD、无 ptrace、不超时，七条绊线全绕过。还有一个更阴的变体：`SHELLOPTS=xtrace` 从环境直接启用跟踪，`_am` 的 `$-` 检查要到 VM 派发阶段才生效，**bootstrap 自身（密钥推导公式所在）已先被整段打到 stderr**。

**修复（三处，合计约 40 行）**：

1. `elfrun.c` 在所有 exec 路径之前：`unsetenv` 掉 `BASH_ENV`、`ENV`、`PS4`、`BASH_XTRACEFD`、`SHELLOPTS`
2. V6 bootstrap 首行（覆盖 V6 单独分发场景）：`set +x` + `unset BASH_ENV ENV PS4 BASH_XTRACEFD` + `trap - DEBUG`
3. `_am()` 增第八条绊线：`[ -n "$(trap -p DEBUG 2>/dev/null)" ] && _pm=0`，防运行中途重新布陷阱

**回归测试**：`BASH_ENV` 指向陷阱文件运行产物，断言两条——输出与参考一致、dump 文件为空。只验其一都是假通过。`SHELLOPTS=xtrace` 变体同样入测。

**效果**：零门槛运行时 dump 关闭。剩余运行时攻击需 root + Frida，且 `_am` 每个指令块都查一次 TracerPid，中途 attach 也会被抓——这是现有设计里被低估的优点，值得写进 README。

### 4.2 打开 _PK 口令模式（杀路径 A，顺带杀 B）

**原理**：主密钥不再来自文件，而是 `K = KDF(口令, salt)`，salt 随机内嵌，口令永不落盘。文件在手而无口令时静态分析物理解不开——这是唯一具有密码学意义的改法，且 V6 已实现原料位（`_M`），只差打开开关并接到 C 层。

**实施要点**：

- **KDF 选型**：优先 argon2id；不愿引外部依赖就用 PBKDF2-HMAC-SHA256（`crypto_core.h` 现成 HMAC，迭代不少于 60 万）。现有 sha512^N 家啤拉伸迭代深度低两个数量级，且报告者已破解过同款思路，应替换
- **口令传递**：经 stdin 或继承 fd（`V7_PASSFD=N`）读入，绝不进 argv（`/proc/*/cmdline` 可读）
- **两层同源**：C 层 blob 根密钥从 urandom seed 换为口令派生；V6 的 `_M` 同步并入密钥链。L2、L3 同时免疫静态爆破，路径 B 的环境枚举因密钥原料多了口令熵一并失效
- **交互**：TTY 时首启提示输入；非交互接受 fd 传入；口令错误表现为 MAC 失败（rc=114），与篡改不可区分，不产生额外 oracle

**代价**：分发链路需带口令；无人值守场景（cron、自动化）要么本机存口令（回到本机可提取问题），要么接受每次注入。私有部署完全可接受，公开分发要权衡。

## 5. P1：杀通用脱壳机（路径 D）

攻击者逆向一次就能对全部后续产物产出脚本，这是比单点漏洞更大的放大器。P1 的每项都独立生效、组合后质变。

### 5.1 per-build 随机化（改 blobgen 与 v7_build 的模板生成逻辑）

| 项 | 做法 | 杀伤 |
|----|------|------|
| seed 打散 | 存 `mask[32]` 与 `seed^mask` 两组字节、随机位置，运行期异或重组 | 固定偏移一把梭（0x20560c 类）失效 |
| 派生标签随机 | `V7ENC`/`V7MAC` 改为每构建随机字节串 | 字符串路标消失 |
| 布局随机 | blob 之间插入随机长度 padding，数组顺序打乱 | 结构指纹失效 |
| 诱饵 blob | 若干组假 seed + 假密文 + 假 tag，真组由运行期不透明计算选定 | 提取脚本必须真分析而非模式匹配 |
| memfd 命名 | `"v7"` 改为每构建随机或空串 | `/proc/*/fd` 侧信道少一个标记 |

实施注意：`V7_SEED` 环境变量覆盖（固定 seed 构建，篡改测试依赖）必须保留；测试套件的密文定位逻辑从"固定偏移"改为"密文锚点搜索"（现有 tamper 测试已经是锚点法，无需改）。

### 5.2 常数表掩蔽

K256[64] 以 `K^mask` 形态存储，首次调用前解掩到可写缓冲；ipad/opad 立即数同法。算法保持标准（两侧共用 `crypto_core.h` 不变），只藏存储形态。指令流里残留的立即数交给 OLLVM（§6.4），此处不必强求。

### 5.3 诊断出口的权衡

退出码 113/114 是给攻击者的免费反馈渠道（可试探"哪层拦了我"）。生产构建可选随机化映射，排障版保留固定值。代价是远程排障必须用 `V7_DIAG=1` 构建的产物，需在 README 写清。

## 6. P2：纵深防御（按场景选做）

### 6.1 设备锁定模式 V7_LOCK（对自用场景几乎免费）

现有工作流本来就是**在目标手机的 Termux 里构建**——构建机指纹即目标机指纹。新增 `V7_LOCK=1`：L3 环境熵从"版本 × ABI × 指纹"（数百组合）扩为 `ro.build.fingerprint` 全串哈希（唯一）。同一台手机的 adb shell 上下文里 getprop 结果一致（r9 已处理过同类跨上下文问题，指纹与执行上下文无关），换机即拒跑。这是**无口令的轻量替代**，适合"只在自己设备跑"的用法；对外分发仍需 §4.2。

### 6.2 补齐报告以为有、实际没有的防御

| 项 | 报告声称 | 实际 | 建议 |
|----|---------|------|------|
| PR_SET_DUMPABLE(0) | 有 | 无 | 补。注意 execve 会重置 dumpable，只护 C 层解密窗口；bash 子进程无法 prctl，靠 `_am` 持续检查兜底 |
| PATH 净化 | 有 | 无（仅 PATH 为空时补默认值） | 不建议白名单化（会误杀 toybox 环境），`unsetenv` 注入变量系（§4.1）已覆盖实质风险 |
| /proc/self/maps 扫描 | 有 | 无 | 可选。扫 frida/gum 特征段名，对 gadget 注入有效；ptrace 类已被 TracerPid 盖住 |

### 6.3 已有优点，保持并文档化

- `_am` 每指令块查 TracerPid：Frida 中途 attach 也会被抓，不是只在启动时查
- 载荷解密后 `unset _code`：明文驻留窗口极短，堆扫描只能抓碎片
- CEXEC 诱饵造成静态/动态各有盲区：静态要分析全部 60 块，动态只执行 30 块
- V6 变量名 per-build 随机化：报告者被迫走爆破路线而非读变量名，证明有效

### 6.4 OLLVM / 字符串加密的定位

单独做价值有限——攻击者不需要读懂代码，只要拿到数据。**配合 §5.1 之后才质变**：布局随机 + 控制流不可读，逐产物人工成本暴涨。工具链成本高、稳定性风险真实存在，放最后，做之前先评估 §4.2 与 §5 的完成度。

## 7. P3：架构级（真正的"物理解不开"）

| 方案 | 原理 | 代价 |
|------|------|------|
| 服务端密钥下发 | 产物只含半钥，运行期经认证拉取另半（可叠加 Play Integrity） | 需服务端与联网，部署模型变更 |
| TEE / StrongBox | 密钥入硬件，CPU 外不可读 | 需 APK 打包，脱离独立 ELF 形态 |

P0 的口令模式已让纯静态物理失效；P3 解决的是"持口令者 dump"与"root 真机 hook"，那已越出文件保护范畴进入 DRM 领域。业界共识：客户端最终持明文终可被取，只能抬高成本。

## 8. 诚实边界

1. bash 执行前必须拿到明文命令，这个窗口物理上关不掉；root + Frida 且肯花时间的攻击者终能到
2. 持口令者（合法用户）永远可在 eval 处 dump；口令模式防的是文件泄漏，不防持钥者
3. 安全性等式：攻击成本 > 资产价值。"不可能还原"只在密钥不在文件里（§4.2）或不在本机（§7）时成立

## 9. 攻击成本对比

| 阶段 | 静态（T1 / T3） | 运行时（T2） |
|------|----------------|--------------|
| r9 现状 | 全破已实锤，脚本可量产 | BASH_ENV 零门槛 dump |
| +P0 | 无口令 = 物理不可解 | 需 root + Frida + 绕 8 条绊线 + 伪造 /proc |
| +P0+P1 | 口令泄漏后仍需逐产物人工逆向，无通用脚本 | 与 P0 持平（随机化对动态无增益） |
| +P3 | 离线分析全灭 | 攻击面转移到服务端 / TEE，不同量级 |
