# 架构与设计原理

三层独立的保护，可单独使用，也可叠加：

```
V6（脚本层）  →  V7（ELF 层）  →  V7-ISA（解释器层）
 混淆算法        反调试封装        令牌化去语义
```

---

## 一、总体分层

```
┌────────────────────────────────────────────────────────────────┐
│  L0  环境门控                                                   │
│      按配置拒绝非目标环境（编译期固化，防沙箱分析）              │
│      ⚠️ 注意：门控是"可选开关"而非"平台限制"——                   │
│         ANDROID_GATE=0 即可在任何 Linux 环境使用               │
├────────────────────────────────────────────────────────────────┤
│  L1  外层封装                                                   │
│      V7: ELF 加载器（载荷追加宿主尾部 + 定长尾读）               │
├────────────────────────────────────────────────────────────────┤
│  L2  载荷加密                                                   │
│      scrypt-like KDF + Encrypt-then-MAC + 流式解密              │
│      磁盘永无明文；明文走 pipe 即写即抹                          │
├────────────────────────────────────────────────────────────────┤
│  L3  语义令牌化（V7-ISA）                                       │
│      命令名/关键字/字符串/标识符 → 加密表映射                    │
│      ★ 解释器语言特有的最大优势：粒度到每一条命令                │
├────────────────────────────────────────────────────────────────┤
│  L4  运行时对抗                                                 │
│      反调试 / 反注入 / 反内存读取（seccomp / TracerPid）         │
├────────────────────────────────────────────────────────────────┤
│  L5  执行者保护                                                 │
│      VMP 保护"翻译表 + 解密的执行者"                            │
│      ⚠️ 收益有边界（见 VMP_NOTES.md）                          │
└────────────────────────────────────────────────────────────────┘
```

## 二、V6：混淆算法层

**核心目标**：让"解出脚本"必须**真实执行**，而不是静态推导。

### 2.1 五阶段流水线

```
split_into_blocks     分块（按语法结构切分，保证每块可独立 eval）
      ↓
compile_v5            每块 → 密文（AES-256-CTR，逐项独立密钥流）
      ↓
prepare_passkeys      密钥分离（可选）：包裹主密钥 M
      ↓
generate_output_v6    生成解释器 + 两表结构
      ↓
compact_output_file   压缩（贪心合并，减小体积）
      ↓
inject_integrity_hash 完整性三重自校验
      ↓
inject_hself          骨架自哈希 H_skel
      ↓
finalize_layer1       一层壳（必须最后）
```

> **顺序敏感**：`finalize_layer1` 必须在最后，否则一层壳会被后续步骤破坏。

### 2.2 两表结构

```
_c[]  加密指令批表     \x01 分隔，INST_BATCH=16 条/批
_d[]  加密数据块表     六行同构：det / beacon / 原码 / rt=$_ rc=$? / _s / _ck
```

### 2.3 三个核心机制

**① 执行状态绑链（`_s`）**

```bash
# 块 i 的 _s 掺入前一块的真实执行状态
_s = f( rt=$_ , rc=$? , pp=执行路径 )
# 六种排列随机选一（防模式识别）
```

→ 攻击者**不能静态推导**，必须真实执行前一块并得到相同的 `$?`/`$_`。

**② 跳跃式密钥链（JUMP_DIST=7）**

```bash
# 第 N 块额外掺入第 N-7 块的 _ck
jump_ck="${CK_HISTORY[$((i - JUMP_DIST))]:-}"
```

→ 从中间 dump **无法向后重建**，必须**从头完整执行**。

**③ 批级自修改（`_am`）**

```bash
_rs = (_rs * 1103515245 + 12345) & 0x7fffffff   # LCG
RANDOM=$_rs; _ra=$RANDOM; _rb=$RANDOM           # 重播种 + 消费
_mk = sha512(_mk + _p + _ra + _rb)[0:16]
_c[$_p] = $(_e "$_b" "$_mk" "$_p")              # 重加密整批
```

→ 内存 dump **一次性**——即使拿到某刻密钥，下一秒就变。

### 2.4 伴生机制

| 机制 | 作用 |
|---|---|
| **不透明谓词** | 类型 0-3 恒真（`di+1`/`di*di+1`/`di+di+2`/`di*2+1`），4-7 恒假。只用 `+ - *`，避开 `==`/`%` |
| **诱饵块**（DECOY_LEVEL） | 走恒假谓词，**零执行** |
| **垃圾块**（JUNK_LEVEL） | 走**完全相同**的 compile_v5 路径，**真实 eval**，参与密钥链 |
| **契约名随机化** | 每次构建重命名全部内部变量 |
| **完整性三重自校验** | 归一化比对骨架/密文/字面量三处 |
| **V6_NS 命名空间** | 个人化前缀 + per-build 随机后缀（署名感与安全性兼得） |

## 三、V7：ELF 封装层

### 3.1 双路线

| 路线 | 结构 | 特点 |
|---|---|---|
| **A：外挂 ELF** | 父解密 + 子解释器 | 实现简单，但跨进程有明文窗口 |
| **B：魔改解释器内嵌** | **单进程** | **能单进程就单进程**（重要结论） |

### 3.2 载荷布局（blob v3）

```
[ct][tag 16][salt 16][N 4 LE][wb_table 256][wb_perm 256][wb_mask 256][flags 4 LE][len 4 LE]
 len = ctlen + 812
```

- **定长尾读**：从文件尾反向定位，不依赖头部偏移
- 两种模式（口令/白盒）共用布局

### 3.3 密码学

```
kenc = HMAC(seed, "V7ENC")
kmac = HMAC(seed, "V7MAC")
流密钥块 i = HMAC(kenc, be64(i))[32B]
tag = HMAC(kmac, ct)[16B]        ← Encrypt-then-MAC
```

**scrypt-like KDF**：PBKDF2 → ROMix（N=131072 → 16MB 顺序填充 + 随机回访）→ PBKDF2

### 3.4 流式执行（路线 B）

```
父进程:
  分块（4096）解密 → 写 pipe（即写即抹，明文不进磁盘）
  每次 write 前 waitpid(WNOHANG|WUNTRACED) + child_being_traced
子进程:
  exec 魔改 bash，读 /proc/self/fd/N
```

**对抗 `SIGSTOP` 冻结 + 管道排空攻击**：
- `WUNTRACED`（检测子进程被冻结）
- 写端 `O_NONBLOCK`
- `F_SETPIPE_SZ` 缩到一页（4K）——**缓冲区小，明文驻留量最小**

### 3.5 反调试五件

| 检测 | 手段 |
|---|---|
| TracerPid | 读 `/proc/self/status` |
| 注入 | 扫 `LD_PRELOAD` |
| 时间窗 | 解密耗时异常（**VMP 构建下关闭**——VM 解释慢与调试停顿不可区分） |
| frida | 扫自身 maps 的 frida 痕迹 |
| 执行期 | 轮询子进程 TracerPid |

任一命中 → `die(113)`。

### 3.6 内存擦除三层纵深

| 层 | 手段 | 边界 |
|---|---|---|
| **PR_SET_DUMPABLE=0** | 非 root 断读 | root 可绕 |
| **seccomp-BPF 黑名单** | 拦 `ptrace`/`process_vm_readv`/`process_vm_writev` | 各架构 syscall 号不同 |
| **mlock + MADV_DONTDUMP + MADV_WIPEONFORK** | 防换页 / 防 core / 防 fork 泄露 | — |

## 四、V7-ISA：令牌化层

**核心思想**：让产物在磁盘上**只是一串随机令牌**。

### 4.1 四层表

| 层 | 内容 | 数量 | 插桩点 |
|---|---|---|---|
| **L1** | 内建命令 | 8 | — |
| **L2** | 外部命令 | 9 | `execute_simple_command` |
| **L3** | 关键字 | 13 | `CHECK_FOR_RESERVED_WORD` **宏** |
| **L4** | 变量 + 路径 | 13 + 5 | `variables.c` / 路径 hook |
| **L6** | 字符串字面量 | — | 密文驻留（`orig_ct` + `orig_off`） |

> **L3 的关键坑**：主路径是 **`CHECK_FOR_RESERVED_WORD` 宏**，而 `find_reserved_word` 是**旁路死代码**（无调用者）。打在后者上 → L3 全程不生效，且**静默失败**。

### 4.2 令牌化四个技术点

1. **真名不进表**——只存 `sym_id`（表内去语义化，真名在 C 层符号表）
2. **密文驻留**——避免内存中出现 `{别名, 真名}` 明文配对
3. **混合串子串扫描**——形态预检 + 精确查表 + 容量 fail-safe
4. **词边界锚定**——裸 `strstr` 血案：`sha512` 里的 `f054` 被误改成 `/data`

### 4.3 所有权契约（三次迭代）

```
v1  返回 static 表指针      → bash FREE 非堆地址 → 堆损坏
v2  返回 strdup 拷贝        → 外层 RESIZE 时 xrealloc 非自己 chunk → 炸
v3  只返回【视图】          → 宏负责 RESIZE + strcpy + 同步 token_index  ✅
```

> **教训**：hook "替换字符串"前先问**指针归谁**、后续会不会被 `realloc`/`free`。
> **改内容安全，换 owner 是把炸弹埋到下游几十行之外。**

## 五、构建顺序（不可颠倒）

```
编译链接
  → 导出符号快照（.map）      ← 必须在加固前！
  → VMP 保护（可选）
  → 抹节区头（anti-disassembly）
  → 剔除诊断串
```

**原因**：加固后符号就再也导不出来了。**这个顺序极易漏，后果最重。**
