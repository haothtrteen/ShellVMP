# 开源范围说明

> 这份文档明确说明：**哪些开源、哪些保留、为什么**。
>
> 写这份文档本身就是一种专业信号——避免"看起来缺了什么"的猜测，也让使用者清楚知道自己在用什么。

---

## 一、原则

> **开源"怎么想"，保留"怎么调"和"怎么用"。**

- **机制公开**不削弱安全性（Kerckhoffs 原则）：安全性应依赖**密钥**，不依赖**算法保密**
- 而且机制公开会让项目**更可信、更容易被引用**，也避免"别人抢先发论文说这是他做的"
- **参数与运维保留**才是实际优势所在

---

## 二、分层清单

| 层 | 状态 | 理由 |
|---|---|---|
| **V6 混淆算法**（分块/绑链/跳跃密钥链/自修改） | ✅ **开源** | 教材级内容；算法公开不削弱安全性 |
| **V7 加载器 + 密码学核心** | ✅ **开源** | 同上。开源 = 更多人帮找 bug |
| **全套文档 / 方法论 / 心路历程** | ✅ **开源** | 最好的名片 |
| **工具**（lint / diag / 定位 / 对接） | ✅ **开源** | 工程工具本身就是价值 |
| **V7-ISA 插桩点位置与接口** | ⚠️ **公开方法，保留实现** | 这是工程量最大、最难复现的部分 |
| **完整 tokenization patch 集合** | ❌ **保留** | 每个语言都要重找插桩点，这是护城河 |
| **真机构建链路（特定环境适配）** | ❌ **保留** | 与具体业务环境绑定 |
| **最优参数组合预设** | ❌ **保留** | 公开"有哪些旋钮"，保留"最优旋钮组合" |
| **真机产物二进制** | ❌ **不分发** | 体积 + 隐私 |

---

## 三、为什么 V7-ISA 只公开方法

V7-ISA（解释器魔改令牌化）是这个项目**技术含量最高的部分**，但它的**价值不在代码本身**，而在：

1. **插桩点的选择**（在 bash 源码的哪个位置下手）
2. **所有权契约的处理**（三次迭代才稳定）
3. **与具体源码版本的适配**（bash 5.2 的源码结构）

其中：

- **1 和 2 的价值在"知道为什么"**——这部分本仓库**公开**（见 [`TOKENIZATION.md`](TOKENIZATION.md)）
- **3 的价值在"具体怎么改"**——这部分**保留**

本仓库提供的是**简化示例 + 完整的插桩点说明**，足够你理解原理并自行校准。

## 四、如果你要用在商业项目

| 你想做 | 用开源的够吗 |
|---|---|
| 保护自己的 shell 脚本 | ✅ **够**——V6 + V7 完整可用 |
| 理解方法论并移植到别的语言 | ✅ 够（文档齐全） |
| 要 V7-ISA 的完整实现 | ⚠️ 需要自行校准插桩点（有文档指导） |
| 要经过实战调优的参数组合 | ❌ 需要自己调 |

## 五、对贡献者的说明

欢迎提交：

- 🐛 **Bug 报告**：附**产物 + 复现命令 + 期望行为**
- 📖 **文档改进**：尤其是"你踩了什么坑"——这类内容最有价值
- 🧪 **测试用例**：请遵循"**逐字节对拍**"原则
- 🔌 **新语言移植**：请附**机制可移植性分析**（哪些能抄、哪些要重做）

**不接受**：

- ❌ 声称"提高强度"但没有实测数据的 PR
- ❌ 引入未经审计的第三方密码学实现
- ❌ 移除"诚实边界"章节的文档改动

---

## 六、安全问题报告

如果你发现了**能绕过保护**的方法：

1. **请勿公开披露**
2. 通过仓库的 Security Advisory 私下报告
3. 附最小复现

我们会：

- 确认后**优先修复**
- 在 `docs/PITFALLS.md` 记录（用"实测打脸"的口吻，不带攻击细节）
- 在 Release Notes 致谢

> 我们**欢迎**被攻破——**一份诚实的 "实测打脸清单" 比一份虚假的 "无法破解" 承诺有价值得多。**
