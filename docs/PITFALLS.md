# 踩过的坑（按症状索引）

> 这份文档按**症状**组织，方便你遇到类似现象时快速定位。
> 每一条都是真实踩过的，附根因和修法。

## 一、静默算错类（最危险）

这类 bug **不崩溃、不报错**，只是悄悄输出错误结果。**头号敌人。**

### 1.1 产物 rc=0、输出截断、无任何报错

| 项 | 内容 |
|---|---|
| **症状** | 混淆后脚本跑一部分就停，退出码 0，无报错，输出被截断 |
| **根因** | **随机变量名撞名**。25 个变量从 62² 空间抽取，撞名概率约 **8%**。某块的 `rt_name` 撞上解释器改名后的循环计数变量 → 运行时 `rt_name=$_` 把循环计数覆盖成信标串 `__xxxxxx__` → `[ p -lt n ]` 报错 → **VM 静默提前退出** |
| **修法** | 变量名注册表**必须落文件**——所有调用点都是 `rt_name="$(gen_rand_var)"` 这种子 shell 形式，bash 数组 `+=` 的注册**无法传回父进程**，注册表永远是空的。文件注册表对子 shell 持久 |
| **相关** | `gen_rand_var()` |

### 1.2 产物解出来是 base64 垃圾

| 项 | 内容 |
|---|---|
| **症状** | 运行产物输出一堆 base64 乱码 |
| **根因** | 同上的撞名，但撞的是**链变量** → 密钥链分叉 |
| **修法** | 同上 |

### 1.3 KDF 结果错（VMP 化后）

| 项 | 内容 |
|---|---|
| **症状** | VMP 保护后，KDF 输出与未保护版本不一致 |
| **根因** | **内联引入 SIMD 指令**。`-O2` 内联进来的 `memcpy` 用上了 `STP qN`（128 位 SIMD 拷贝），而 VM 只有通用寄存器 |
| **修法** | `-mgeneral-regs-only` + `-fno-inline` **双管齐下**；必须做**数值对拍** |
| **相关** | [`VMP_NOTES.md`](VMP_NOTES.md) |

### 1.4 V6 产物"跑几条就停"

| 项 | 内容 |
|---|---|
| **症状** | 产物执行几条命令后停止 |
| **根因** | **宿主 `errexit`**。脚本第 7 行裸 `false`（`set -e` 下直接退出）。查了三轮才落地 |
| **修法** | 混淆前先跑 `python3 tools/v6_lint.py your_script.sh` |

### 1.5 产物静默 exit、零提示

| 项 | 内容 |
|---|---|
| **症状** | 产物什么都不输出，直接退出 |
| **根因** | 脚本内 `set -x` / 改 `PS4` / 重定义 builtin 命中**反调试指纹** → 主密钥污染（`_mk` 被静默破坏） |
| **修法** | `tools/v6_lint.py` 静态检查；运行期用 `tools/v6_pm_diag.sh` 逐项诊断 6 个条件 |
| **注意** | 这是**设计行为**（毒化 > 报警），但用户需要知道为什么 |

### 1.6 引号内后面的路径常量还原不了（**改写域 ≠ 还原域**）

| 项 | 内容 |
|---|---|
| **症状** | `echo "/system/bin/sh /data/adb/m1"` 输出 `/system/bin/sh v7p_9z0hq01cwr/m1` —— **第一个还原了，后面的没还原**。无报错，只是**静默输出错内容**（比崩更难发现） |
| **根因** | **改写器与还原器的作用域不一致**。`v7_isa.py` 的 `rewrite_all` 在**引号内整段参数**里做子串替换（4 个 token 全换）；而 C 侧 `v7_isa_path_step` 用 `strncmp(cur, alias, alen)` **只在词首匹配**（只还原第 1 个）。这是 r17-1 留下的"防误伤锚定"——防误伤防过了头 |
| **修法** | 放宽为**全词扫描**，但**保留左右边界判据**（左须词首/分隔符，右须非标识符字符）。别名长 14 字符（`v7p_` + 10 位随机段），叠加上下文判据后撞车概率仍可忽略 |
| **教训** | **防误伤的锚定必须与改写器的实际作用域同宽。** 不是越窄越安全 —— 窄于改写域 = 静默语义破坏，比误伤更难发现（没有报错，只有错输出） |
| **证据** | `tools/isa_itest.py` 的 `l4_path` 用例（修复后转绿） |

### 1.7 数组元素赋值被当成业务字符串 → L6 构建失败

| 项 | 内容 |
|---|---|
| **症状** | `v7_build.sh` 报 `ValueError: L6 真名超长（1021 > 512）`，整条 L6 链路构建失败 |
| **根因** | `tools/v7_isa.py` 的 `_is_assignment_rhs` 只认 `NAME="..."`，**不认 `arr[i]="..."`**。回扫变量名时 `[`/`]` 不是 alnum/underscore，循环止于 `]`，取出的 name 是 `"0]"`（首字符是数字）⇒ 判为"非赋值右侧"。于是 V6 产物的指令池 `_uO[i]` / 代码块池 `_3c[i]` 里那些**上千字节的密文块**全被当作"业务字符串"提取 |
| **修法** | 回扫前先剥掉尾部下标。注意**配对要整体扫**：`m[1][2]` 这类嵌套下标，逐层 `depth` 递减会在第一个 `]` 处提前 break |
| **教训** | `extract_static_strings` 的"保守策略"写在注释里（"拿不准的一律跳过"），但**数组赋值这个形态漏了**。V6 产物大量使用 `arr[i]=` 形态，这个洞在纯明文脚本上测不出来 |
| **证据** | 修复前提取 18 条（16 条 >512B）；修复后 V6 产物提取 0 条、明文脚本仍正确提取 9 条业务串 |

## 二、崩溃类

### 2.1 `munmap_chunk(): invalid pointer`

| 项 | 内容 |
|---|---|
| **症状** | 四层改写脚本跑到第 9 行必崩，gdb 指向 `read_token_word` 的 `RESIZE_MALLOCED_BUFFER` |
| **根因** | hook 返回了 **static 表指针**，bash 词法器 `FREE(token)` 释放非堆地址 |
| **修法** | 三次迭代（见下） |

```
v1  返回 static 表指针    → FREE 非堆地址
v2  返回 strdup 堆拷贝    → 把文件作用域 static 的 token 指向 malloc 小块，
                             parse_matched_pair 递归回词法器时内层也会改它，
                            外层回来炸
v3  只返回视图            → 宏负责 RESIZE + strcpy 拷回 + 同步 token_index ✅
```

> **通用教训**：hook「替换字符串」前先问**指针归谁**、后续会不会被 `realloc`/`free`。
> **改内容安全，换 owner 是把炸弹埋到下游几十行之外。**

### 2.2 VMP 化后 SIGSEGV

| 症状 | 根因 | 修法 |
|---|---|---|
| 函数体过大，语义错 | VM 对复杂函数处理缺陷 | 拆**外部链接** helper 瘦身 |
| VMP 后 SIGILL（rc=132） | **函数边界圈进了邻居函数**。符号表里两个相邻符号之间可能夹着无符号的本地函数 | 用反汇编**精修函数边界**（见下） |

**函数边界精修的坑**：

```
错误做法：用"下一个符号地址"当函数结束
  → 会圈进夹在中间的无符号函数
  → VMP 把它一起加密替换
  → 运行时落到被加密指令上 → SIGILL(rc=132)

正确做法：从起点反汇编，遇到【新函数序言】立即停止，返回最后一个 ret 之后

★ 只认【预索引】形式：stp x29, x30, [sp, #-N]!
  有些函数自己的序言是 sub sp,sp,#N + stp x29,x30,[sp,#M]（非预索引）
  若按宽松匹配，本函数自己的序言会被当成"下一个函数"而提前截断
  （实测 hmac_sha256 被截成 12 字节）
```

## 三、构建期类

### 3.1 "分支目标超出函数范围"（VMP 拒保）

| 项 | 内容 |
|---|---|
| **根因** | 内联/尾跳/块重排产生跨区间分支 |
| **修法** | `-fno-inline -fno-ipa-cp-clone -fno-optimize-sibling-calls` |

**一个具体的血案**：

```
-O2 把 static isa_load 内联进 v7_isa_init 并拆出 cold part
→ wrapper 只剩 20B + 尾部跨函数分支
→ VMPacker 报"分支目标超出函数范围"拒保

修法：ISA_HOOK_FLAGS = V7CORE_FLAGS + -fno-inline -fno-ipa-cp-clone
```

### 3.2 保护面悄悄少一项（**构建成功**）

| 项 | 内容 |
|---|---|
| **症状** | 构建成功，但某个该保护的函数没被保护 |
| **根因** | `static` 函数被 `-O2` 内联，**符号从符号表消失** |
| **修法** | 各编译单元加 `-fno-inline`；**加符号存在性断言**（缺一个就 `exit 1`） |
| **注意** | **没有这条断言，你永远不知道保护面少了谁** |

### 3.3 判定解释器不能用 `-x`

| 项 | 内容 |
|---|---|
| **症状** | 跨架构构建时，`bash -n` 报"子块语法不自洽"，错误指向用户脚本 |
| **根因** | `-x` 判据在异构 ELF 上**为真**（有 +x 位）却跑不起来（x86 宿主 + aarch64 ELF）。于是选中"直连执行"分支 → `Exec format error` → 被解读成"块语法不自洽" |
| **修法** | 以**能否真正执行**为判据：`"$1" -c 'exit 0'` 探针 |

### 3.4 `--build-id` 造 PT_NOTE 锚点

| 项 | 内容 |
|---|---|
| **症状** | VMP 注入失败 |
| **根因** | 某些 VMP 工具以 **PT_NOTE 段为注入锚点**，而链接产物没有 `.note.*` |
| **修法** | 链接时加 `-Wl,--build-id` 造一个锚点（内容无意义） |

### 3.5 少 `--disable-nls` → V6 产物静默跑不动

| 项 | 内容 |
|---|---|
| **症状** | 从源码编出的 bash 跑 V6 产物，**第一个块之后就静默 `exit 1`（零输出、零报错）**。极易误判成"改动把保护功能弄坏了" |
| **根因** | configure 少了 `--disable-nls`。带 NLS 时 locale/消息目录相关路径的行为差异让 V6 骨架的自校验链走不通 |
| **修法** | 用 `build_poc.sh` 的完整参数：`--disable-readline --disable-nls --without-bash-malloc` |
| **排查法** | 用 `--version` 比对宿主 bash 与自编 bash，再**逐步二分插桩**（先只换 `zread.c`+`v7core.c`，再加上游 patch，再加 ISA hook）。本次正是靠二分定位的 |
| **注意** | 系统 bash 能用、自编的不能用时，**先怀疑 configure 参数，不要怀疑自己的插桩** |

### 3.6 手工注入 Makefile 后 `libsh.a` 陈旧

| 项 | 内容 |
|---|---|
| **症状** | 链接期 `undefined reference to v7_harden_install`，但 `lib/sh/v7_harden.o` **确实存在** |
| **根因** | 对象文件编出来了，但没进 `libsh.a` 归档（手工 sed 注入 OBJECTS 后，库的增量重建没跟上） |
| **修法** | `rm -f lib/sh/libsh.a && make`；或直接用 `build_poc.sh`（它会断言三条编译规则都在） |
| **补刀判据** | `ar t lib/sh/libsh.a \| grep v7_` 看四个对象是否齐 |

### 3.7 ISA 表 bin 与 json 不同源

| 项 | 内容 |
|---|---|
| **症状** | `isa_itest.py` 报"改写对了但运行输出不一致"，看起来像 C hook 坏了 |
| **根因** | 测试用 **json** 改写，二进制读 **bin**。改完表只更新了 json、bin 还是旧的 ⇒ 同一 alias 在两份表里指不同真名 |
| **修法** | 改表后同步重导 bin。排查时先比对：`deserialize(bin)` 的 alias→orig 与 json 是否逐条一致 |
| **教训** | 见到"还原成了另一个合法但错误的词"（如 `then` 变 `fi`），**第一反应查表的同源性**，别先怀疑 hook |

## 五、逻辑/设计类

### 5.1 hook 点打在死代码上（**假成功**）

| 项 | 内容 |
|---|---|
| **症状** | L3 令牌化"看起来生效了"，实际全程不生效 |
| **根因** | 打在 `find_reserved_word` 上——它是**旁路死代码**（无调用者）。词法主路径是 **`CHECK_FOR_RESERVED_WORD` 宏** |
| **识破方式** | stderr 里的 `alias not found` |
| **修法** | 改打**宏体首行** |
| **通用教训** | **插桩点必须选在主执行路径**。验证方式：patch 点后打探针，探针必须真命中 |

### 5.2 懒初始化 vs 门控

| 项 | 内容 |
|---|---|
| **症状** | 裸 bash 下 ISA 表永不装载 |
| **根因** | `v7_isa_init` 挂在 `v7_init` 下 → 被 `V7_SELF` 门控 |
| **修法** | 改**懒初始化**（`isa_tried` 哨兵，首次翻译时装载），与 blob 流程解耦 |

### 5.3 `$N` 位置参数的 hook 恒无效

| 项 | 内容 |
|---|---|
| **症状** | L4 位置参数改写无效，且**静默取空值** |
| **根因** | bash 的 `$N` 走 **`param_expand` 的 `case '0'..'9'`** → 直接取 `dollar_vars[]`，**不经 `find_variable`** |
| **修法** | 正确 hook 点在 `param_expand` switch **之前** |
| **注意** | **静默取空值比报错更危险** |

### 5.4 禁用型 patch 用 `#ifdef`，注入型用 `#ifndef`

| 项 | 内容 |
|---|---|
| **症状** | 明知有 `BASH_ENV` 回显，patch 后仍被 source |
| **根因** | **宏方向用反了** |
| **修法** | **禁用型**（包整段）用 `#ifdef`；**注入 return 型**用 `#ifndef` |

### 5.5 混合串子串扫描的血案

| 项 | 内容 |
|---|---|
| **症状** | `sha512` 里的 `f054` 被误改成 `/data` |
| **根因** | 裸 `strstr` 没有词边界检查 |
| **修法** | **词边界锚定**（词首锚定 + 右边界校验） |

## 六、"我以为但实测打脸"清单

这几条是最值得记住的——它们推翻了"理所当然"的直觉：

| 我以为 | 实测结果 |
|---|---|
| `PROT_NONE` 能拦住 `/proc/pid/mem` 读取 | ❌ **拦不住**。内核走 `get_user_pages`，**不检查页表权限** |
| `unset` 能擦除内存 | ❌ **不擦**。密文留下 5 份副本、明文留下 8 份递减前缀 |
| "窗口式保护"有用（只在解密瞬间暴露） | ❌ 8 线程高频轮询，**命中率 99.9995%** |
| `free` 之后内存就干净了 | ❌ chunk 会被复用，**擦过的零被覆盖成调用方数据** |
| 加密了就不会被篡改 | ❌ 没有 MAC 时，**乱码会被 `eval`** |
| "每条用不同密钥"就安全 | ❌ 只要密钥间有关联（如由行号派生），**已知明文一步推出全部** |
| 密钥不写在文件里就安全 | ❌ 只要**派生算法明文**，攻击者可以自己跑一遍 |

## 八、跨 shell 兼容（新增，2026-09-14）

> 这一组坑的共同特征：**在 bash 下单 shell 测永远发现不了。**
> 它们是"编译期模拟 ↔ 运行期执行"两侧取到不同值导致的密钥链分叉，
> 表现为**静默 `exit 1`**（无报错、无输出），最难排查。
>
> 排查入口：`tools/sh_compat_check.sh`

### 8.1 `$RANDOM` 是密钥链的头号杀手

| 项 | 内容 |
|---|---|
| **症状** | 产物在 mksh 下静默 `exit 1`；bash 完全正常 |
| **根因** | bash 的 `$RANDOM` 是 Park-Miller/Schrage LCG，**mksh 用另一套算法，dash 根本没有 `$RANDOM`**。生成器的编译期模拟器逐位复刻了 bash 的 LCG，运行期却用宿主的 `$RANDOM` → 密钥分叉 |
| **实测** | `RANDOM=1` → bash `16807 10791 19566`；mksh `25858 19392 12422` |
| **修法** | 新增 `_rn()`：纯算术内联 PRNG，复刻 bash 5.1+ `lib/sh/random.c`（Park-Miller + Schrage 防溢出 + `(r>>16)^(r&0xffff)` 折叠 + 重复值重摇）。**三 shell 下逐位一致** |
| **顺带** | 该方案**作废了 C 层补丁** `dash-random-hook.patch`——不需要改任何 shell 源码 |

#### 8.1.1 `_rn()` 的三条附加约束（r33f 实锤，少一条就静默 `exit 1`）

`_rn()` 写对了算法还不算完 —— 它必须同时满足下面三条，否则症状和 8.1 一模一样（产物只输出第一个块，然后 `exit 1`，**零报错**）：

| # | 约束 | 违反后果 |
|---|---|---|
| ① | **必须进 `gen_randomized_interpreter` 的 sed 重命名表** | `_am` 被改名，`_am` 体内的 `_rn` 调用却留字面 → `_rn: command not found` → `_ra/_rb` 取值失败 → 密钥分叉 |
| ② | **定义必须写在 `_am()` 之后** | builtin 模式下生成器用 awk 把 `^_f() {` 到 `^_am() {` 之间整段替换为 awk 版函数体 —— 定义落在这段区间内会被**整段删除**，产物里连函数都不存在 |
| ③ | **内部临时变量不得占用 `_rt`** | `_rt` 是**永不改名**的契约名（块间传递 `$_`）；`_rn` 内部若用 `_rt` 做临时量，会把契约值冲掉。改用 `_rq` 等私有名 |

还有一条最容易漏的：

> **`_rn` 不能用 `$(...)` 捕获。** `$( )` 会 fork 子 shell，`_rr`/`_rl` 的更新留在子进程里出不来 —— 每次调用都从同一状态出发，返回同一个值。实测 `_rs=42` 时 `$(_rn)` 三次全部得 `17772`（正确序列是 `17772 26794 1435`）。
> **正确写法**：`_rn` 把结果写入全局 `_ro`，调用点写成 `_rn; _ra=$_ro`。

验证手法（不碰产物，只测函数）：

```sh
_rs=42; _rr=$(( _rs & 0xFFFFFFFF )); _rl=0
_rn; a=$_ro; _rn; b=$_ro; _rn; c=$_ro
echo "sim: $a $b $c"                  # 期望 17772 26794 1435
bash -c 'RANDOM=42; echo "bash: $RANDOM $RANDOM $RANDOM"'
```

两行必须一致。**这是判断 `_rn` 是否正确的唯一快速手段** —— 不一致就一定是子 shell 或变量名的问题，不必去解产物。

### 8.2 `$_` 在 mksh/dash 里不是"上一条命令的最后一个参数"

| 项 | 内容 |
|---|---|
| **症状** | 同上，静默 `exit 1`；且难定位到具体构造 |
| **根因** | 产物每块前插信标 `true "<随机串>"`，块尾 `rt=$_` 捕获。bash 的 `$_` 确实是"上一条命令的最后一个参数"，**但 mksh/dash 的 `$_` 恒为 shell 自身路径**（`/usr/bin/mksh`）。这是 POSIX 未定义行为 |
| **实测** | `true "__beacon42__"` 之后：bash `$_=__beacon42__`；mksh `$_=/usr/bin/mksh`；dash `$_=/usr/bin/dash` |
| **修法** | **不要求 `$_` 回放任何东西**。把信标字面量内联进捕获行，并保证 `$?` 语义不丢：<br>`rt=$_ rc=$?` → `rc=$? rt="<beacon>"` |
| **代价** | 失去"用户块是否改写了 `$_`"这一防御维度。`$_` 本身是 bash 扩展，无移植替代。`rc` 与 `pp` 仍强制掺入，前序链完整 |
| **注意** | `rc=$?` **必须在 `rt=…` 之前**（赋值会重置 `$?`）。且这个新写法**不影响位置参数**（`$@`/`$1` 原样） |
| **残余抖动** | `aes_small` 用例偶发单次失败（`S01 begin` 之后即停）。重跑即过，连跑 20 次约出现 1 次。根因在 §1.1 的撞名空间：块数少的样本上 `rt_name`/`_s` 派生对 `$_` 的时序窗口更窄，属于**已知残余**而非本次回归。判据：**单次失败先重跑，连续两轮失败才算真故障**。彻底修法见 §1.1（扩大名字空间或改回确定性派生） |

### 8.3 `$-` 每个 shell 都不一样

| 项 | 内容 |
|---|---|
| **症状** | 同上 |
| **根因** | `$-` 是"当前生效的选项标志串"，bash `hB`、mksh `hU`、dash 空串 |
| **修法** | 从密钥公式里去掉 `$-`，换成一个**可移植推出的常量**（交互性用 `case $- in *i*` 单独判定） |
| **连带** | 编译期同步把硬编码的 `"hB"` / `6` 改成与运行期同形的 `"n"` / `$#`，保持两侧对称 |

### 8.4 `read -a` 在 mksh 里按"字符码"建数组

| 项 | 内容 |
|---|---|
| **症状** | 解释器解出的指令流错位；`_K8=67`（`C` 的 ASCII 码）而不是字符串 `"C"` |
| **根因** | `IFS=$(printf '\001'); read -r -a arr <<< "a\x01b\x01c"` 的行为：<br>· bash：`count=3`，值为 `a` `b` `c` ✓<br>· mksh：**`count=5`**，值是**数字字符码** `97 1 98 1 99`<br>· dash：`<<<` 语法直接报错 |
| **修法** | 换成 POSIX 的 `IFS` + 位置参数切分（三 shell 实测结果完全一致）：<br>`IFS=$(printf '\001'); set -f; set -- $str; set +f`<br>消费端从 `for x in "${arr[@]}"` 改为索引 `while` + `eval "x=\${$i}"` |

### 8.5 `builtin type -t` / `declare -f` / `[[ ]]` 是 bash 专有

| 项 | 内容 |
|---|---|
| **症状** | 反调试守卫用 `[[ $- == *x* ]] && exit 1` 直接语法报错 |
| **根因** | 生成器注入的 `DETS` 守卫载荷用了 bash 扩展 |
| **修法** | `[[ $- == *x* ]]` → `case $- in *x*)`；`builtin type -t X` → `command -V X`（匹配 `*builtin*`）；`[ -z "$(declare -f eval)" ]` → `case "$(command -V eval)" in *function*)` |
| **注意** | mksh 支持 `builtin eval/source/command/exec/read`，但**不支持** `builtin type` / `builtin printf` |

### 8.6 产物上做文本替换是徒劳的

| 项 | 内容 |
|---|---|
| **症状** | 用 `sed` 改完产物，运行直接 `exit 1`（或输出为空） |
| **根因** | 产物有 `_hs` 自完整性校验：把自己的内容（`_I` / `_hs` 行归一化为空后）哈希，与内嵌值比对，不符即退 |
| **修法** | **所有修正必须走生成器模板**，由生成器在构建时重算 `@@HSELF@@`。产物文本替换 = 触发自毁 |
| **推论** | 解释器是 `eval` 展开的（`eval "$_D"`），其代码**不在产物文本里**——`<(…)`、`read -a` 这类必须改生成器的 heredoc 模板，改不到产物上 |

### 8.7 诊断这类问题的有效手法

| 手法 | 说明 |
|---|---|
| `mksh -x <产物>` | mksh 的 `-x` 会打印 `typeset '_RJ=…' '_aM=…' '_1v=…'` 形式的**函数入参**，比 bash 的 `-x` 信息更全，是定位 `_Ud` 调用参数的第一手材料 |
| 对齐两 shell 的变量序列 | 用脚本抽取两边 trace 里的 `_RP=` / `_1v=` / `_8s=` / `_oX=` 等赋值行，**逐项 diff 找首个分叉点**——比肉眼看快得多 |
| 注意 bash `-x` 会自毁 | 反调试守卫 `case $- in *x*) exit 1` 在 `bash -x` 下**必然触发**。所以 `bash -x` 不能作为常规诊断手段；用 mksh 的 `-x`，或临时把守卫改宽（仅限本地调试） |
| 对照"改动前"的生成器 | 保留一份改动前快照（如 `gen.pre_rt.bak`），在失败样本上对比新旧输出行数，可立刻判定"是我引入的还是既有的" |

#### 8.7.1 别去解产物 —— 用「最小增量变体」二分（r33f 实锤有效）

V6 的解释器是 `eval` 展开的、数据块逐块 MAC 绑定、还有链式自校验和"毒化密钥静默退出"。**对它插桩（拦截 `eval`、dump `$_D`、替换解密点）本身就会破坏行为** —— 你看到的失败可能正是插桩造成的，最坏情况是把一个确定的问题查成一个不确定的问题。这一次用插桩查了几轮，每轮结论都不同，全程零收获。

真正解决问题的是一条不需要碰产物的路：

1. **拿一个已知能跑的旧快照**当基线，先确认它在当前环境确实能跑（这次是用户提供的 `TShell.zip`）。
2. **把新生成器的改动逐项"反向应用"到旧快照上**，每加一项就生成 + 跑一次 `test_big.sh`，看是否复现失败。
3. 复现失败的那一项，就是元凶。这次一次命中：只把 `_am` 里的 `RANDOM=$_rs; _ra=$RANDOM; _rb=$RANDOM` 换成 `_rr=…; _ra=$(_rn); _rb=$(_rn)` 就复现了。
4. **再把元凶拆到最小函数单独测**（见 8.1.1 的 `_rn` 三行验证），不经过生成器和产物 —— 直接暴露 `$( )` 子 shell 问题。

一句话：**对外部行为复杂的黑盒，不要从内部插桩去理解它；从"已知好的版本"出发做增量二分，把问题逼到能独立复现的最小单元上。** 这条同样适用于排任何"静默算错"类问题。

### 8.8 门禁脚本本身要能"优雅跳过"

| 项 | 内容 |
|---|---|
| **坑** | 交叉验证脚本若把"某个 shell 没装"判为失败，会长期红灯；**长期红的灯等于没有灯** |
| **修法** | 缺 shell → 明确列出并跳过，不计失败。已归档不做的 shell（zsh）→ 标为**信息性观测**，不参与判定 |
| **坑** | `ksh` 在多数发行版是**指向 mksh 的符号链接**。不去重会把同一实现计为两个 shell 并双双报"一致"，制造虚假信心 |
| **修法** | 用 `readlink -f` 取真实路径去重 |
