# VMP 对接笔记与收益边界

> **核心结论先说**：**VMP 是"保护函数体"的手段，不是"保护明文"的手段。**
> 对本架构（脚本最终交给解释器 `eval`），VMP 的收益**有限但非零**。上之前请先读完本文。

---

## 一、值不值得上：三道筛子

| 筛子 | 通过条件 | 本项目的实际情况 |
|---|---|---|
| **① 明文窗口在保护面内吗** | 关键明文只在被保护函数里出现 | ⚠️ **不通过**——V6 骨架最终交给 `eval`。VMP 保护的是 V7 壳，`eval` 那一刻的明文**没保护到** |
| **② 关键函数能否独立出来** | 未被 `-O2` 内联 | ✅ 通过（`V7_NOINLINE=1`） |
| **③ 能否满足 VM 约束** | 零 NEON/FP、体积不过大 | ⚠️ 需要 `-mgeneral-regs-only` 改造 |

**结论**：筛子①的限制是**架构决定的**。VMP 能保护 V7 壳的密码学核心（密钥派生、HMAC、KDF），但**保护不了 `eval` 的明文**。

---

## 二、那还有没有价值

**有，但要说清楚是什么价值**：

| 保护对象 | 价值 |
|---|---|
| 密钥派生函数（`v7_keys`） | ✅ **高**——拿到即能解密全部载荷 |
| 完整性校验（`blob_verify`） | ✅ **高**——patch 成恒真即关闭整套校验 |
| 令牌翻译（`v7_isa_translate*`） | ✅ **高**——拿到即等于明文 |
| 反调试判据（`traced`/`anti_frida`） | ✅ 中——patch 掉即绕过检测 |
| **`eval` 的明文** | ❌ **保护不到**（架构限制） |

**一句话**：**VMP 让"攻击者读懂 V7 壳"变难，但不让"攻击者拿到 `eval` 的明文"变难。** 这两件事是不同的。

## 三、实测记录

### 3.1 VMPacker 的实测结论

| 项 | 结果 |
|---|---|
| 能解析我们的 anti-disassembly 产物吗 | ✅ 能（走 Program Header，不依赖 section header） |
| 主要拒保原因 | **NEON/FP 指令**（VM 只有通用寄存器） |
| 加 `-mgeneral-regs-only` 后 | ✅ 可保护（运行时零 NEON） |
| 函数体大小是否相关 | ⚠️ 相关但**非因果**（192B 修好、140B 仍错） |
| 保护后体积 | +~15KB（VM 解释器段） |

### 3.2 反汇编产物仍可被工具解析

这印证了那条原则：

> **抹节区头是"抬门槛"，不是"消除能力"。** Ghidra/IDA/VMPacker 走 Program Header 照读。

## 四、对接流程（工具无关）

```
① 编译链接（带 V7_VMP=1 的编译开关）
     -fno-inline -fno-inline-small-functions
     -fno-ipa-cp-clone -fno-optimize-sibling-calls
     -mgeneral-regs-only

② 导出符号快照（.map）        ← 必须在保护前！
     readelf -sW out.elf | awk '$4=="FUNC"{print "0x"$2,$8}' > out.elf.map
     或 nm -S --defined-only out.elf | awk '$2=="T"||$2=="t"{...}'

③ 定位保护函数
     有 .map  → 按名字（推荐）
     无 .map  → tools/vmp_targets.py 启发式定位

④ 逐函数"保护 + 运行验证"     ← 最实用的一招
     for 每个候选：
         vmpacker -addr "<区间>" -o try.elf in.elf
         接回尾部载荷
         与基线对拍（rc/stdout/stderr）
         一致 → 保留；不一致 → 剔除并记录原因
     用幸存清单批量保护一次

⑤ 一次性批量保护（不要链式！工具输出会自动去符号）

⑥ 接回尾部载荷                ← 最易漏
     VMP 工具只认识 ELF image，会丢掉追加在段之后的 blob
     必须按【新产物自身】的段边界重算接回

⑦ 全量验证（逐函数都过、组合可能冲突）

⑧ 后处理：抹节区头 → 剔除诊断串（勿再 strip）
```

## 五、核心工具

### 5.1 `tools/vmp_apply.py`

自动化对接，内置**逐函数验证闭环**：

```bash
# 只列出计划
python3 tools/vmp_apply.py out.elf --dry-run

# NEON 体检
python3 tools/vmp_apply.py out.elf --check-neon

# 逐函数验证 + 自动剔除坏函数 + 幸存清单批量保护
python3 tools/vmp_apply.py out.elf --verify --vmpacker /path/to/vmpacker
```

**关键设计**：
- **NEON 体检**：capstone 逐指令扫，凡出现 `q/d/v/s` 寄存器或 FP 助记符即拒绝
- **函数边界精修**：只认**预索引序言**，避免截断/圈进邻居
- **尾部载荷接回**：自动检测并接回 blob
- **基线归一化**：清掉 `4ms`/`memfd=N` 这类非确定性输出（否则所有函数被误判"行为变化"）
- **基线双跑**：跑两次一致才可用（产物本身不确定 → 验证不可信）

### 5.2 `tools/vmp_targets.py`

**无符号表产物**里的保护函数定位（四步启发式）：

| 步骤 | 做法 |
|---|---|
| 1 特征字符串交叉引用 | 搜 `V7ENC`/`TracerPid`/`LD_PRELOAD` 等，反查 ADRP+ADD 找引用函数 |
| 2 常量指纹 | 搜 SHA-256 K 表头，命中 ±0x100 = 真在跑该算法 |
| 3 调用图 | 建 BL 调用边，做函数→函数闭包 |
| 4 距离过滤 | 离 `main` 超阈值一律判 SKIP（libc 噪音） |

输出三档：`[MUST]` / `[SHOULD]` / `[SKIP]`。

## 六、常见故障

| 症状 | 根因 | 修法 |
|---|---|---|
| 拒保"分支目标超出函数范围" | 内联/尾跳 | `-fno-inline -fno-ipa-cp-clone -fno-optimize-sibling-calls` |
| 保护面悄悄少一项（**构建成功**） | `static` 被内联，符号消失 | 加 `-fno-inline` + **符号断言** |
| 拒保（提示含 SIMD） | 函数或序言碰了 NEON | `-mgeneral-regs-only`；重写 16 字节比较为 GPR 循环 |
| 翻译成功但静默算错 | 内联引入 SIMD；或译码器缺陷 | 去内联+去 NEON；数值对拍；仍错则禁该函数 |
| SIGILL(rc=132) | 边界圈进邻居 | 精修函数边界 |
| "完整性校验失败"但无报错 | **尾部载荷被丢弃** | 保护后按新段边界接回 |
| rc=113 | VM 变慢触发时间窗 | VMP 构建关闭时间窗检测 |
| 逐函数都过、合起来崩 | 函数间冲突 | 幸存清单批量后整体验证；二分缩小 |

## 七、跨语言提示

| 提示 | 说明 |
|---|---|
| **ELF VMP 工具都吃 ELF** | 先问"关键逻辑在 ELF 里，还是在解释器读的字节码里？" |
| **字节码语言（`.pyc`/Lua 字节码）** | VMP 工具管不到 → 要么魔改解释器，要么接受"保护面 = 加载器" |
| **改造 1/2/3 跨语言不变** | 去内联 / 去 NEON / 精修边界 |
| **"符号快照必须先导出"** | 跨语言最容易漏、后果最重的一条 |

## 八、退而求其次：当 VMP 打不动时

| 手段 | 防护点 | 成本 | 风险 |
|---|---|---|---|
| **每构建常量随机化** | 废掉定位关键函数的明文路标 | **极低** | 低 |
| 符号抹除 + anti-disassembly | 抬静态分析门槛 | 极低 | 低（**抬门槛 ≠ 消除**） |
| 敏感函数用 `-mgeneral-regs-only` 从头写 | 为将来上 VMP 铺路 | 中 | 低 |
| 拆小函数 + 去内联 | 让保护面"可保护" | 中 | 低 |
| **整函数 VMP** | 即使定位到函数也只剩字节码 | **高** | 中 |

> **实测结论：对本架构，先把"每构建常量随机化"用满，比上 VMP 值钱得多。**
>
> **VMP 最适合的场景**：**独立的小体积、纯 GPR 的关键校验函数**（如 license 校验、单一哈希比较），且**最好从一开始就用 GPR-only 写**。
